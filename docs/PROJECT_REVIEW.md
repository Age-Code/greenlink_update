**결과 표기**

권장 사항으로 남긴 항목은 운영 데이터 마이그레이션, 서명 키 같은 외부 준비물, 팀의 정책 결정이 필요한 것들입니다.

| # | 관점 | 점검 결과 | 조치 |
|---|---|---|---|
| 1 | 인증·세션 | JWT에 `tokenVersion`을 넣어 로그아웃·탈퇴·비밀번호 변경 시 즉시 무효화되는 구조는 좋습니다. 다만 **로그인 시도 횟수 제한이 없어** 비밀번호 무차별 대입이 가능했습니다. | ✅ 같은 이메일로 10분 안에 5번 실패하면 10분 잠금하고 429로 응답합니다(앱·관리자 웹 공통, `LoginAttemptLimiter`). |
| 2 | 비밀번호 정책 | 최소 4자였고, 앱 가입 화면에는 입력 검증이 없었습니다. | ✅ 새 비밀번호는 8자 이상 100자 이하입니다(가입·변경). 앱 가입 화면에서도 미리 검사합니다. 기존 계정 로그인에는 영향이 없습니다. |
| 3 | 비밀값 관리 | DB 접속 정보, JWT 키, OAuth 비밀값은 `.env`나 `application-keys.yaml`로 외부화되어 있습니다. Kakao 네이티브 키는 앱 4곳에 하드코딩되어 있지만 공개용 키입니다. | ⚠️ 장치 키(`iot_device.device_key`)가 **평문 저장**입니다. 해시 저장으로 바꾸려면 운영 DB 키를 일괄 변환해야 하고, 되돌릴 수 없어 이번에는 하지 않았습니다. 진행 시 `sha256:` 접두사 방식과 배포 시점 일괄 변환을 권장합니다. |
| 4 | IoT 통신 | Pi는 requests로 HTTPS 인증서를 검증합니다. ESP32는 루트 인증서 관리가 어려워 TLS 검증을 생략합니다(암호화는 유지). | ⚠️ 필요하면 ESP32에 Cloudflare 루트 CA를 넣고 `setCACert`로 검증합니다. 카메라 MJPEG은 인증이 없으므로 **Cloudflare Access 적용을 권장**합니다. |
| 5 | 하드웨어 안전 | 급수는 서버와 Pi 양쪽에서 1초 상한입니다. 릴레이는 NO 접점을 쓰고, 부팅 시 GPIO를 HIGH로 고정합니다. 5분 지난 명령은 자동 취소됩니다(이전 작업). | ✅ 유지. 배선·부팅 안전 절차는 `HARDWARE_WIRING.md`에 있습니다. |
| 6 | 동시성·무결성 | 급수(펌프 행 락)와 보상 수령(퀘스트 행 락)은 비관적 락으로 직렬화되어 있습니다. 출석, 재배 공간 연결, 펌프 채널은 unique 제약이 있습니다. | ⚠️ 조명 명령 중복 검사는 락이 없어, 같은 순간 두 요청이 오면 2건이 생길 수 있습니다. 결과가 멱등(켜기/끄기)이라 영향은 작습니다. |
| 7 | 성능 | 인벤토리 조회가 아이템 종류마다 count 쿼리 3개, 도감은 식물 종마다 쿼리 1개를 보냈습니다(N+1). | ✅ 인벤토리는 1회 조회 후 메모리에서 집계하고, 도감은 내 식물을 1회 조회해 종별로 묶습니다. ⚠️ 관리자 목록 화면은 엔티티를 직접 렌더링해 LAZY N+1이 남아 있습니다(데이터가 적어 당장은 무방). |
| 8 | 비즈니스 규칙 | **자동 급수도 사용자의 "물 주기" 퀘스트 진행도를 올려**, 사용자가 아무것도 하지 않아도 퀘스트가 완료됐습니다. | ✅ 자동화가 만든 급수 명령은 퀘스트 진행에서 제외합니다. |
| 9 | 개인정보·로그 | 앱이 로그인·가입 때 이메일과 닉네임을 로그로 남겼습니다. `debugPrint`는 릴리스 빌드에서도 출력됩니다. | ✅ 이메일·닉네임 로그를 제거했고, 릴리스 빌드에서는 `debugPrint`를 끕니다. |
| 10 | 오류 처리 | 관리자 폼 검증, IoT 화면의 일시 오류 처리는 이전 작업에서 개선했습니다. | ✅ 429(요청 과다) 응답을 공통 형식(`ApiResponse`)으로 추가했습니다. |
| 11 | 운영 | Docker 로그 크기 제한이 없었고, DB 백업 절차와 Pi 로그 정리도 없었습니다. | ✅ compose에 로그 크기 제한(10MB×3)을 걸고, `scripts/backup_db.sh`(gzip, 14일 보관)와 `greenlink_pi/logrotate.conf`를 추가했습니다. |
| 12 | DB 스키마 관리 | `ddl-auto=update`이고 마이그레이션 도구가 없습니다. 이번 변경에는 컬럼 추가가 없어 기존 DB에 그대로 배포할 수 있습니다. | ⚠️ 스키마가 바뀌기 시작하면 Flyway를 도입하고 운영은 `JPA_DDL_AUTO=validate`로 바꾸는 것을 권장합니다. |
| 13 | 테스트·CI | 테스트는 있었지만 자동 실행(CI)이 없었습니다. | ✅ `.github/workflows/ci.yml`을 추가했습니다. 백엔드(JDK 17), Flutter(analyze·test), Pi(unittest)를 푸시·PR마다 실행합니다. |
| 14 | 앱 배포 준비 | 패키지명이 `com.example.front`이고 릴리스 빌드도 debug 키로 서명합니다. 토큰은 SharedPreferences에 평문 저장하며 refresh token이 없습니다(24시간 후 재로그인). | ⚠️ 스토어 배포 전에 패키지명 확정, 업로드 키 생성, Google 로그인 SHA-1 재등록이 필요합니다. 토큰은 `flutter_secure_storage`로 옮기는 것을 권장합니다. |
| 15 | 외부 의존성·유지보수 | 관리자 화면이 쓰지 않는 Quill·Handlebars와 중복 jQuery를 외부 CDN에서 불러왔습니다. 쓰이지 않는 리포지토리 메서드가 약 40개 있습니다. | ✅ 쓰지 않는 CDN 스크립트를 제거해 관리자 화면이 로컬 파일만 씁니다. ⚠️ 쓰이지 않는 메서드 정리는 동작 변화가 없어 별도 정리 작업으로 남깁니다. |
